# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## Проект "GameShop" - Онлайн-магазин видеоигр

---

## ВВЕДЕНИЕ

GameShop представляет собой специализированное веб-приложение, разработанное для ценителей видеоигр, которые желают приобретать игры, управлять своей игровой библиотекой и зарабатывать игровую валюту через участие в викторинах. 

Данный продукт позволяет пользователям не просто покупать игры за реальные деньги, но и использовать заработанные в викторине очки для приобретения игр, а также участвовать в игровой рулетке для получения призов. В рамках своего функционала приложение обеспечивает интеграцию с внешними источниками данных (Steam API), что позволяет автоматически получать актуальную информацию о играх, включая такие детали, как изображения, описания, разработчики и издатели.

Однако важно отметить, что продукт имеет четко определенные границы - он не предусматривает социального взаимодействия между пользователями, таких функций как обмен играми или комментирование, а также не поддерживает реальную обработку платежей (используются заглушки для демонстрации функционала).

---

## 1. ТРЕБОВАНИЯ ПОЛЬЗОВАТЕЛЯ

### 1.1. Программные интерфейсы

Архитектура приложения построена на использовании современных программных интерфейсов и технологий. В качестве основной платформы разработки используется Django 5.2.7 - мощный веб-фреймворк на языке Python, что обеспечивает надежную работу и масштабируемость системы. Для организации локального хранения данных применяется встроенная база данных SQLite, которая отвечает за сохранность информации о пользователях, играх, покупках и транзакциях между сеансами работы.

Ключевым внешним компонентом является интеграция с Steam API, который служит источником информации о видеоиграх через Steam ID. Для работы с внешними API используются библиотеки requests и httpx, обеспечивающие асинхронную обработку сетевых запросов. Пользовательский интерфейс построен на основе Bootstrap 5.3.3, что обеспечивает современный и адаптивный дизайн для различных устройств.

### 1.2. Интерфейс пользователя

Пользовательский интерфейс спроектирован с акцентом на интуитивную понятность и современный дизайн, что обеспечивает комфортное взаимодействие даже для неподготовленных пользователей. Навигационная структура приложения включает последовательность логически связанных страниц:

**Главная страница** предлагает обзорную информацию о магазине, отображает горячие акции, распродажи, новинки и категории игр. В навигационной панели представлены основные разделы: Главная, Магазин, Рулетка, Викторина, а также элементы управления аккаунтом (вход, регистрация, пополнение баланса).

**Страница регистрации** включает интеллектуальную систему валидации вводимых данных с проверкой уникальности имени пользователя и корректности email-адреса. После успешной регистрации пользователь автоматически входит в систему.

**Страница авторизации** предоставляет стандартную форму входа с использованием имени пользователя и пароля. После успешной авторизации пользователь получает доступ к полному функционалу магазина.

**Страница каталога игр** содержит табличное представление коллекции игр с элементами управления фильтрацией по категориям и статусам (распродажа, новинки, рекомендуемые). Каждая карточка игры отображает изображение, название, цену, категорию и статус владения.

**Страница детальной информации об игре** отображает полную информацию о выбранной игре, включая описание, разработчика, издателя, дату выхода, а также предоставляет возможность покупки за деньги или очки. Отображается информация о скидках и экономии при распродажах.

**Страница рулетки** предоставляет игровой механизм для получения призов. Пользователь может выбрать рулетку, увидеть возможные призы и совершить вращение за определенную плату. Система отслеживает количество попыток в день (максимум 5 попыток).

**Страница викторины** отображает случайные вопросы с вариантами ответов. За правильные ответы пользователь получает очки, которые можно использовать для покупки игр. Система отслеживает серии правильных ответов.

**Страница пополнения баланса** позволяет пользователю пополнить свой баланс, введя данные банковской карты. Система поддерживает сохранение карт для будущих платежей.

Поведенческие сценарии взаимодействия включают как стандартные действия (клик для просмотра деталей, нажатие кнопок), так и расширенные возможности (фильтрация, поиск), что обеспечивает эффективное взаимодействие с элементами интерфейса.

### 1.3. Характеристики пользователей

Целевая аудитория приложения охватывает широкий спектр пользователей, объединенных интересом к видеоиграм - от случайных игроков до настоящих геймеров, желающих расширить свою игровую библиотеку. Можно выделить несколько ключевых категорий пользователей, каждая из которых обладает специфическими характеристиками и потребностями.

С одной стороны, это **случайные игроки**, которые используют приложение для базового приобретения игр и предпочитают простые, интуитивно понятные интерфейсы. С другой стороны - **активные геймеры**, для которых покупка игр и участие в викторинах для заработка очков является важной частью деятельности и которые ожидают расширенного функционала с возможностями поиска, фильтрации и участия в игровых механиках.

Особое внимание в процессе проектирования интерфейса было уделено пользователям с различным уровнем технической подготовки. Для обеспечения комфортного использования всеми категориями пользователей были реализованы специальные меры, включая понятную навигацию, визуальные индикаторы статусов игр, четкие кнопки действий и информативные сообщения об ошибках.

Уровень технической подготовки пользователей варьируется в широких пределах - от начинающих пользователей веб-приложений до технических специалистов, что обусловило необходимость создания адаптивного интерфейса, предоставляющего простой доступ к базовым функциям для неподготовленных пользователей при сохранении расширенного функционала для опытных пользователей.

### 1.4. Предположения и зависимости

Функционирование приложения основывается на ряде фундаментальных предположений и технологических зависимостей, которые формируют базовые условия его эксплуатационной пригодности. Ключевым требованием является наличие стабильного интернет-соединения, которое необходимо для полноценной работы с внешним API Steam и загрузки изображений игр. Это предположение определяет архитектурные решения, связанные с обработкой сценариев работы при отсутствии сетевого подключения, включая механизмы кэширования и корректного информирования пользователя о состоянии сетевой доступности.

Локальное хранилище данных на сервере, реализованное на основе SQLite, обеспечивает сохранность персональных данных, покупок и транзакций между различными сеансами работы с приложением. Эта зависимость определяет требования к объему памяти сервера, а также обуславливает необходимость реализации механизмов обеспечения целостности данных.

Архитектурные решения предполагают совместимость с современными веб-браузерами (Chrome, Firefox, Safari, Edge), что обеспечивает охват значительной доли пользовательской базы при сохранении возможности использования современных возможностей веб-платформы.

### 1.6. Войти в свою учётную запись

**Описание:** вариант использования «Войти в свою учётную запись». Позволяет пользователю войти в учётную запись.

**Предусловия:** пользователь выбрал способ «Вход» для входа в приложение.

**Основной поток включает в себя:**
1) Приложение отображает форму входа в учётную запись;
2) Пользователь вводит имя пользователя и пароль;
3) Пользователь подтверждает вход;
4) Приложение проверяет учетные данные;
5) Приложение присваивает пользователю статус «авторизован»;
6) Приложение перенаправляет пользователя на главную страницу;
7) Вариант использования завершается.

**Альтернативный поток А1** (неверные учетные данные):
1) Приложение отображает сообщение об ошибке "Неверное имя пользователя или пароль";
2) Пользователь может повторить попытку входа;
3) Возврат к п.2 основного потока.

**Альтернативный поток А2** (отмена):
1) Пользователь нажимает кнопку "Отмена";
2) Приложение закрывает форму входа;
3) Вариант использования завершается досрочно.

**Постусловия:** выполняется вариант использования "Просмотреть каталог игр".

### 1.7. Зарегистрироваться

**Описание:** вариант использования «Зарегистрироваться». Позволяет пользователю создать свою учетную запись в приложении.

**Предусловия:** пользователь выбрал способ «Зарегистрироваться» для входа в приложение.

**Основной поток:**
1) Приложение отображает форму регистрации, в которой запрашивает у пользователя ввод имени пользователя, email и пароля;
2) Пользователь вводит свои данные;
3) Пользователь подтверждает ввод данных;
4) Приложение проверяет введенное имя на совпадение с именами уже зарегистрированных пользователей. Если совпадение обнаружено, оценивается альтернативный поток А2;
5) Приложение проверяет корректность email. Если email некорректен, оценивается альтернативный поток А3;
6) Приложение проверяет соответствие паролей. Если пароли не совпадают, оценивается альтернативный поток А4;
7) Приложение создает учетную запись пользователя с начальным балансом 0 и 0 очков;
8) Приложение автоматически входит пользователя в систему;
9) Приложение перенаправляет пользователя на главную страницу;
10) Вариант использования завершается.

**Альтернативный поток А2** (существующее имя пользователя):
1) В сообщении сообщается, что пользователь с таким именем уже существует;
2) Приложение запрашивает у пользователя ввод другого имени;
3) Возврат к п.2 основного потока.

**Альтернативный поток А3** (некорректный email):
1) В сообщении сообщается об ошибке валидации email;
2) Приложение запрашивает у пользователя ввод корректного email;
3) Возврат к п.2 основного потока.

**Альтернативный поток А4** (несовпадение паролей):
1) В сообщении сообщается, что пароли не совпадают;
2) Приложение запрашивает у пользователя повторный ввод паролей;
3) Возврат к п.2 основного потока.

**Альтернативный поток А5** (отмена):
1) Пользователь нажимает кнопку "Отмена";
2) Приложение закрывает форму регистрации;
3) Вариант использования завершается досрочно.

**Постусловия:** выполняется вариант использования "Просмотреть каталог игр".

### 1.8. Просмотреть каталог игр

**Описание:** вариант использования «Просмотреть каталог игр» загружает информацию о доступных играх в магазине.

**Предусловия:** пользователь вошёл в приложение или зарегистрированный пользователь открыл страницу магазина.

**Основной поток включает в себя:**
1) Приложение получает список всех доступных игр из базы данных;
2) Приложение получает список игр, принадлежащих пользователю (если пользователь авторизован);
3) Приложение отображает игры из каталога в виде карточек с изображениями, названиями, ценами и статусами. Если список пустой, то показывается альтернативный поток А4;
4) Вариант использования завершается.

**Альтернативный поток А4** включает в себя:
1) Приложение отображает сообщение пользователю об отсутствии игр в каталоге;
2) Вариант использования завершается.

**Дополнительная информация:** пользователь может применять фильтры по категориям и статусам (распродажа, новинки, рекомендуемые).

### 1.9. Фильтровать игры

**Описание:** вариант использования «Фильтровать игры» отбирает игры в соответствии с выбранными критериями.

**Предусловия:** пользователь находится на странице каталога игр.

**Основной поток включает в себя:**
1) Пользователь выбирает категорию или статус (распродажа, новинки, рекомендуемые);
2) Приложение получает выбранные критерии фильтрации;
3) Приложение фильтрует список игр по выбранным критериям;
4) Приложение отображает отфильтрованный список игр;
5) Вариант использования завершается.

### 1.10. Просмотреть детальную информацию об игре

**Описание:** вариант использования «Просмотр детальной информации об игре» отображает полную информацию о выбранной игре.

**Предусловия:** пользователь нажал на карточку игры в каталоге или на кнопку "Подробнее".

**Основной поток включает в себя:**
1) Вариант использования начинается, когда пользователь выбирает игру в каталоге;
2) Приложение получает идентификатор выбранной игры;
3) Приложение получает полную информацию об игре из базы данных;
4) Приложение проверяет, принадлежит ли игра пользователю (если пользователь авторизован);
5) Приложение отображает детальную информацию о фильме, включая описание, разработчика, издателя, дату выхода, цены, скидки;
6) Вариант использования завершается.

### 1.11. Купить игру за деньги

**Описание:** вариант использования «Купить игру за деньги». Позволяет зарегистрированному пользователю приобрести игру за реальные деньги.

**Предусловия:** зарегистрированный пользователь просматривает детальную информацию об игре и нажал кнопку «Купить картой».

**Основной поток включает в себя:**
1) Пользователь нажимает кнопку «Купить картой» в окне с информацией об игре;
2) Приложение проверяет наличие игры в библиотеке пользователя. Если игра найдена, оценивается альтернативный поток А6;
3) Пользователь вводит данные карты (заглушка);
4) Пользователь подтверждает покупку;

## 2. СИСТЕМНЫЕ ТРЕБОВАНИЯ

### 2.1. Функциональные требования

К функциональным требованиям относятся:

- **Регистрация с валидацией:** длина имени пользователя от 3 символов, проверка уникальности, валидация email-адреса, проверка совпадения паролей
- **Авторизация:** вход по имени пользователя и паролю с проверкой учетных данных
- **Управление балансом:** пополнение баланса с возможностью сохранения карт для будущих платежей
- **Каталог игр:** отображение всех доступных игр с фильтрацией по категориям и статусам (распродажа, новинки, рекомендуемые)
- **Детальная информация об игре:** отображение полной информации включая описание, разработчика, издателя, дату выхода, цены, скидки
- **Покупка игр за деньги:** приобретение игр с использованием банковской карты (заглушка), предотвращение повторной покупки
- **Покупка игр за очки:** приобретение игр за заработанные в викторине очки с проверкой достаточности средств
- **Система викторины:** отображение случайных вопросов, начисление очков за правильные ответы, отслеживание серий правильных ответов
- **Система рулетки:** игровой механизм для получения призов с ограничением попыток (5 в день), автоматическое добавление выигранных игр в библиотеку
- **Управление библиотекой:** отслеживание купленных игр, отображение статуса владения
- **Интеграция с внешними API:** получение информации об играх через Steam ID
- **Административная панель:** управление играми, категориями, пользователями, рулетками через Django Admin

### 2.2. Нефункциональные требования

К нефункциональным требованиям относятся:

- **Надежность:** стабильная работа при нестабильном соединении, обработка ошибок сетевых запросов, целостность данных при транзакциях
- **Производительность:** асинхронная обработка сетевых запросов, оптимизация запросов к базе данных, время загрузки страниц не более 3 секунд
- **Безопасность:** защита от SQL-инъекций, CSRF-защита, валидация входных данных, безопасное хранение паролей (хэширование)
- **Удобство использования:** интуитивный интерфейс для неподготовленных пользователей, адаптивный дизайн под различные разрешения экранов, понятная навигация
- **Совместимость:** поддержка современных веб-браузеров (Chrome, Firefox, Safari, Edge), корректное отображение на разных пропорциях экранов
- **Масштабируемость:** модульная архитектура Django, возможность добавления новых функций, поддержка расширения функциональности
- **Поддерживаемость:** чистый код, документация, использование стандартных практик Django
